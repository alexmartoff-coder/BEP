# BEP — Сервис генерации коммерческих предложений (КП)

Стартовый шаблон веб-сервиса автоматического создания коммерческих предложений (КП) на электрощитовое оборудование по спецификациям из PDF-файлов.

Проект разработан с использованием **FastAPI** для бэкенда и чистого **HTML + CSS + JS** для фронтенда. Подготовлен к автоматическому деплою на **Railway**.

---

## 🏗️ Структура проекта

```text
├── backend/                  # Бэкенд на FastAPI
│   ├── main.py               # Основной файл приложения и эндпоинты
│   ├── requirements.txt      # Зависимости бэкенда
│   └── test_main.py          # Автоматические тесты
├── frontend/                 # Статический фронтенд (SPA)
│   ├── index.html            # HTML-разметка интерфейса
│   ├── style.css             # Стили оформления
│   └── script.js             # Логика загрузки PDF и отображения данных
├── .env.example              # Шаблон файла окружения
├── .gitignore                # Файлы, исключённые из Git-репозитория
├── Dockerfile                # Docker-файл для деплоя
├── railway.toml              # Конфигурация для деплоя на Railway
└── requirements.txt          # Общие зависимости (дублируют backend/requirements.txt для Railway)
```

## 🚀 Как запустить локально

### 1. Подготовка окружения

Убедитесь, что у вас установлен **Python 3.11** или новее.

Создайте и активируйте виртуальное окружение:

```bash
# Создание виртуального окружения
python3 -m venv venv

# Активация на macOS/Linux:
source venv/bin/activate

# Активация на Windows (cmd):
venv\Scripts\activate.bat

# Активация на Windows (PowerShell):
venv\Scripts\Activate.ps1
```

### 2. Установка зависимостей

Установите необходимые библиотеки:

```bash
pip install -r requirements.txt
```

### 3. Создание файла конфигурации

Скопируйте пример файла окружения:

```bash
cp .env.example .env
```

### 4. Запуск сервера

Запустите FastAPI сервер с помощью uvicorn:

```bash
uvicorn backend.main:app --reload --port 8000
```

После запуска:
* **Фронтенд** будет доступен по адресу: [http://localhost:8000/](http://localhost:8000/)
* **Интерактивная API Документация (Swagger UI)**: [http://localhost:8000/docs](http://localhost:8000/docs)

## 🛠️ API Эндпоинты

### `GET /api/health`
Проверка работоспособности сервиса. Возвращает статус сервиса.

### `POST /api/upload-pdf`
Принимает PDF-файл со спецификацией оборудования.
* **Request Header**: `Content-Type: multipart/form-data`
* **Form Data**: `file` (PDF-документ)
* **Response**: JSON-объект с извлечённым текстом и структурированным списком распознанных позиций оборудования (в текущей стартовой версии используется заглушка).

Пример ответа:
```json
{
  "status": "success",
  "filename": "specification.pdf",
  "content_type": "application/pdf",
  "extracted_text": "...",
  "items": [
    {
      "id": 1,
      "name": "Вводно-распределительное устройство (ВРУ-1)",
      "quantity": 1,
      "unit": "шт"
    }
  ]
}
```

## ☁️ Деплой на Railway

Проект полностью настроен для деплоя на платформу **Railway** двумя способами:

1. **Через GitHub Integration**:
   Просто подключите ваш репозиторий к Railway. Он автоматически обнаружит `railway.toml` и `Dockerfile`, настроит сборку и запустит проект.

2. **Через Railway CLI**:
   Установите CLI и выполните команду в корневой папке проекта:
   ```bash
   railway up
   ```

Railway автоматически проверит работоспособность сервиса через эндпоинт `/api/health`.
